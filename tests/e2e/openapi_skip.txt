# systemRestart would terminate the daemon under test. The endpoint is also
# opt-in (EnableRestartEndpoint: false in E2E harness), so the route is not
# mounted and the walker sees 404 rather than the documented 202.
systemRestart -- terminates the daemon; route not mounted in E2E harness

# logout is exercised by TestRESTSessionLifecycle. The mutation walker uses
# Basic-Auth headers so session state does not affect walker correctness,
# but calling logout mid-run clears the cookie jar and produces a misleading
# 204 in the mutation coverage table.
logout -- covered by TestRESTSessionLifecycle; side-effects disrupt walker

# getHistory is opt-in (persistence.history.enabled defaults to false). The
# route is therefore not mounted in the E2E harness and the walker sees 404
# rather than a documented status — same situation as systemRestart. Covered
# by handler unit tests in internal/north/rest/handlers/history_test.go.
getHistory -- opt-in feature; route not mounted in E2E harness (history off by default)
# getEnergy is gated on the same persistence.history feature as getHistory: the
# /energy route is only mounted when history is enabled, so it 404s in the E2E

getEnergy -- opt-in feature; route not mounted in E2E harness (history off by default)
