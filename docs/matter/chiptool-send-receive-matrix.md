# chip-tool ↔ daemon ↔ godevccu — per-DP-type send/receive test matrix

Authoritative coverage matrix for the hermetic Matter functional-parity suite: a real
chip-tool commissioner (north) drives the openccu-loom daemon, which is backed by the
in-process **godevccu** CCU simulator (south). Each row exercises a Matter cluster in both
directions — **SEND** (controller write/invoke → CCU `SetValue` ground truth) and **RECEIVE**
(simulated device-originated push → controller proactive Subscribe report). Runs only in the
`chiptool` CI workflow (arm64 + chip-tool + Linux); locally it compiles under `-tags=chiptool`.

Generated from the discovery workflow; see ADR 0048 and `tests/chiptool/`.

## godevccu additions (G1–G8)

- **G1-loader-case** (high): Fleet loader is case-sensitive against embedded filenames; loadAllDevices silently drops HmIP-PS (and would drop HmIP-SWDO/PSM/WRC2 under their marketing spelling) because allowed["HmIP-PS"] != derived "HMIP-PS". No error is surfaced (the >=1-match guard still trips on the other 5 devices). — _../godevccu/internal/ccu/loader.go loadAllDevices (~lines 32-98, the allowed[devName] lookup ~54-58)_  
  Fix: Normalize both the restrict list and derived devName to a canonical case (strings.ToUpper) before building/looking up the allowed map, OR add an alias table for the 4 known all-caps spellings (HMIP-PS/PSM/SWDO/WRC2). Add regression test asserting loadAllDevices([]string{"HmIP-PS"}) returns a non-emp
- **G2-deviceresponses-case** (medium): deviceResponseMappings keys use marketing spelling and Mapping()/startsWith are byte-exact; Mapping("HMIP-PS","STATE")==nil, so stateWithWorking (STATE->{STATE,WORKING:false}) and windowState never apply to the all-caps TYPEs. Primary event still fires via echo fallback, but the derived WORKING/foll — _../godevccu/internal/deviceresponses/deviceresponses.go Mapping() (211-230) + startsWith() (259-264)_  
  Fix: Case-fold both sides of the exact-match and prefix-match comparisons (mirror loom's registry.go ToLower-both pattern) so stateWithWorking applies to HMIP-PS/PSM and windowState to HMIP-SWDO without editing the table keys.
- **G3-simulate-event-primitive** (high): No self-documenting RECEIVE-direction primitive. Authors must call the SEND-shaped SetValue/PutParamset with force=true for every read-only (ops=RE) telemetry param; omitting force returns an explicit 'write not allowed' error — an easy footgun for ACTUAL_TEMPERATURE/HUMIDITY/POWER/ENERGY_COUNTER/MO — _../godevccu/internal/ccu/rpcfunctions.go (new method by SetValue:677/PutParamset:704) + re-export on pkg/godevccu / VirtualCCU_  
  Fix: Add exported func (r *RPCFunctions) SimulateDeviceEvent(address, valueKey string, value any) error = thin wrapper over PutParamset(address, ParamsetAttrValues, map[string]any{valueKey: value}, /*force=*/true) with a doc comment framing it as 'emulate the CCU RF/HmIP layer delivering an unsolicited d
- **G4-computeevents-telemetry** (medium): None of the read-only telemetry params the DefaultDevices fleet needs for RECEIVE tests have explicit deviceResponseMappings entries: BWTH.ACTUAL_TEMPERATURE/HUMIDITY, BSM ch7 VOLTAGE/CURRENT/POWER/ENERGY_COUNTER/FREQUENCY, SWSD.SMOKE_DETECTOR_ALARM_STATUS, plus (for added devices) SMI.MOTION/CURREN — _../godevccu/internal/deviceresponses/deviceresponses.go deviceResponseMappings (36-75)_  
  Fix: Add explicit (even single-key EchoTrigger) entries per device-type/param so the table documents which telemetry params are simulator-settable and a future tightening of the echo default cannot silently break RECEIVE coverage. Add per-DP-type ComputeEvents test cases.
- **G5-blindlevel-activity** (low): Derived-event asymmetry: HmIP-BDT LEVEL write synthesizes ACTIVITY_STATE (levelWithActivity) but HmIP-BROLL/FBL LEVEL write does not (blindLevel), even though the BROLL/FBL paramset descriptions carry ACTIVITY_STATE (ops=RE). — _../godevccu/internal/deviceresponses/deviceresponses.go blindLevel (110-122) vs levelWithActivity (97-108)_  
  Fix: Extend blindLevel's ValueTransformer to also emit ACTIVITY_STATE (non-zero LEVEL -> moving, zero -> idle) so a WindowCovering RECEIVE test gets the same motor-activity signal a BDT test does.
- **G6-action-fire-doc** (low): PutParamset hard-codes the fired value to boolean true for every ACTION-typed param regardless of the argument, and ACTION params are never persisted — so GetValue/GetParamset cannot verify a SEND of an ACTION param (STOP, PRESS_SHORT/LONG, DOOR STOP). — _../godevccu/internal/ccu/rpcfunctions.go (746-759)_  
  Fix: Not a bug (mirrors pydevccu fire-only ACTION semantics) but add an explicit doc comment stating it is deliberate, so the matrix documents ACTION params as event-capture-only (verify via OnSetValue hook / RegisterParamsetCallback, not readback) and a future contributor does not 'fix' it.
- **G7-state-manager-doc** (low): virtualccu State().SetDeviceValue/DeviceValue is a pure cache with zero event-firing (no fireEvent, no RPCFunctions link) yet shares a confusingly similar verb with RPCFunctions.SetValue — a RECEIVE test calling it would silently emit NO event to the daemon. — _../godevccu/internal/state/manager.go (661-674)_  
  Fix: Strengthen the SetDeviceValue doc comment to explicitly cross-reference RPCFunctions.SetValue/PutParamset and state it does NOT fire events and is disjoint from the XML-RPC paramset store. (Doc-only; guards the harness authors from the naming-collision footgun.)
- **G8-fleet-fixtures-pressure-pm** (low): No embedded fixture confirmed to expose AIR_PRESSURE (PressureMeasurement), and no PM2.5/PM10 (MASS_CONCENTRATION_PM_*) fixture exists. CO2 (HmIP-SCTH230) and every other target cluster's representative device ARE already embedded. — _../godevccu/internal/embed/data/{device_descriptions,paramset_descriptions}/*.json_  
  Fix: Author a PressureMeasurement fixture (a weather/air-pressure channel) and, if PM coverage is wanted, a PM2.5/PM10 air-quality fixture. Otherwise DEFER PressureMeasurement + PM2.5/PM10 rows explicitly. (All other rows need NO new godevccu fixture — only DefaultDevices expansion.)
